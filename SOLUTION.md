# Решение для хакатона NtechLab: сквозные треки людей по нескольким камерам

## Что получаем

Программа обрабатывает записи всех камер и выдаёт:

- **число уникальных сквозных треков** и их список;
- для каждого трека — ID, время начала и конца, камеры и интервалы на каждой камере (`tracks.csv` и `tracks.json`);
- **веб-интерфейс**:
  - синхронное видео всех камер;
  - силуэт каждого человека — контур фигуры, залитый цветом его трека, с ID сквозного трека;
  - общее число треков;
  - список треков;
  - шкалу времени: где и когда шёл выбранный трек;
  - план с наблюдаемым и предполагаемым путём.

## Запуск

Для данных организаторов: см. [НОВЫЕ_ВИДЕО.md](НОВЫЕ_ВИДЕО.md). Положите видео в `data/office`, план в `configs/office` и запустите `!start.bat`. Разметка, запуск и просмотр результатов доступны на одном сайте.

Установка на новой машине:

```bash
pip install -r requirements.txt
python scripts/download_weights.py
```

**Проще всего:** положить записи в `data/office`, план в `configs/office` и запустить `!start.bat`, см. [НОВЫЕ_ВИДЕО.md](НОВЫЕ_ВИДЕО.md).

Одной командой вручную — обработать все камеры, склеить их, построить треки и собрать интерфейс. Паспорта перечисляются маской `cam*.json`: маска `*.json` захватила бы и `site.json`.

```bash
python -m mtmc run --passports "configs/office/cam*.json" --data results_office --ui ui_office --site configs/office/site.json
```

Открыть интерфейс:

```bash
python -m mtmc serve --dir ui_office
```

Альтернатива: открыть `ui_office/index.html` двойным щелчком.

Пример на EPFL Lab (готовые паспорта, 4 камеры):

```bash
python -m mtmc run --passports "configs/examples/epfl_lab_6p_c*.json" --data results_6p --ui ui_6p
```

Отдельные шаги:

| Шаг | Команда |
| --- | --- |
| Одна камера: детекция, трекинг, треклеты | `python -m mtmc process --camera <паспорт> --data <папка>` |
| Склейка треклетов всех камер | `python -m mtmc link --data <папка>` |
| Сквозные треки: число и список | `python -m mtmc tracks --data <папка>` |
| Интерфейс | `python -m mtmc ui --data <папка> --out <папка_ui> [--site site.json]` |
| Привязка камеры к плану | `python -m mtmc calibrate --passport <паспорт> --plan plan.png --px-per-m 50` |

### Подготовка данных офиса

1. **Паспорт на каждую камеру.** Скопируйте `configs/examples/epfl_lab_6p_c0.json` и задайте:
   - `cam_id` — номер камеры;
   - `video` — путь к записи;
   - `fps`.

   По ТЗ камеры писали одновременно, поэтому `offset_s` оставляем 0.
2. **Привязка к плану.** Выполните `calibrate` для каждой камеры:
   - окно показывает кадр и план рядом;
   - щёлкните точку на полу в кадре, затем то же место на плане;
   - нужно 6–10 пар точек, разнесённых по полу;
   - клавиша Enter — сохранить.

   Команда записывает в паспорт гомографию H «пиксель → метры плана». Если щёлкать неудобно, точки можно передать файлом через `--points`.
   **Сначала можно попробовать автоматически** (`python -m mtmc autocalib`, подробности ниже, раздел «Автопривязка камер к плану»). Вручную нужно только то, что не получилось.
3. **Файл плана.** `site.json` — картинка плана, масштаб и положение камер. Создаётся в браузере: `plan_office.bat`. Он нужен автопривязке и интерфейсу.

Без H камера обрабатывается, но с другими камерами **не связывается** (`mtmc/link.py`, `_seq_edge`): один человек получает отдельный трек на каждой камере, и на плане его нет. Для сквозных треков H нужна всем камерам.

## Алгоритм

### 1. Одна камера (готовые компоненты)

- **YOLO11m-pose** (ultralytics) — детекция людей и 17 точек позы. Точка «ноги на полу» берётся по щиколоткам; если их не видно — по пропорциям тела.
- **YOLO11m-seg** (ultralytics) — силуэты. Маска фигуры на каждом обработанном кадре сопоставляется с найденным человеком по рамке: жадно, IoU ≥ 0.5. Контур упрощается до ≤ 48 вершин. Шаг идёт после трекинга и не меняет ни треки, ни ID. На EPFL силуэт получили 84–98% наблюдений, около минуты на камеру. Где маски нет, показываются рамка и поза. Команда — `python -m mtmc silhouettes --data <папка>`; в `process` и `run` шаг выполняется сам.
- **BoT-SORT** (ultralytics) — трекинг внутри одной камеры.
- **OSNet x1.0** (torchreid, веса MSMT17) — вектор внешности по кропам.

Фильтр пустых кадров (`mtmc/gate.py`) сохранён, но выключен: детектор проходит все кадры с учётом `stride`. После детектора отбрасываются рамки на экранах и в зеркалах по зонам из паспорта камеры (`ignore_zones`).

Перед переводом на план точки выпрямляются (`mtmc/lens.py`): у камер офиса угол обзора 108–119°, и без этого люди у края кадра попадают на план с ошибкой. Объектив определяется автоматически по прямым линиям сцены.

Своя часть — нарезка треков трекера на **треклеты**: куски, в которых человек точно один. Разрез ставится в четырёх случаях:

- пауза больше 1.5 с;
- физически невозможный скачок на плане (больше 3 м/с с учётом погрешности);
- сильное перекрытие другим человеком: трекер в этот момент часто меняет людей местами;
- резкая смена внешности внутри трека.

На разметке EPFL 6p 96% треклетов чистые.

### 2. Склейка между камерами (своя разработка, модуль `mtmc/link.py`)

**Признаки:**

- **Положение на плане.** Главный признак: гомография переводит точку ног в метры. Два одновременных треклета разных камер считаются одним человеком, если:
  - медиана расстояния между ними ≤ 0.6 м плюс погрешность проекции;
  - большую часть общего времени они ближе 1 м.
- **Внешность.** Косинусная близость средних векторов OSNet. Используется как вето (меньше 0.45 — точно разные люди) и как подтверждение для последовательных кусков.
- **Время и скорость.** Конец одного куска и начало другого: пауза, расстояние, правдоподобная скорость (не больше 2 м/с).

**Запреты склейки:**

- одновременные треклеты одной камеры (два человека в одном кадре);
- одновременные треклеты разных камер дальше 1.5 м друг от друга.

**Объединение:**

1. Жадно: от самых надёжных пар к менее надёжным. Слияние, нарушающее запрет, отменяется.
2. Затем три прохода по уже собранным группам, по их общей траектории.
3. «Мягкое» слияние. Группы, которые долго идут рядом и выглядят одинаково, сливаются, если запретов между ними не больше 10%. Такие редкие запреты — это шум.

Неточная привязка разрывает человека: расхождение на плане больше 1.5 м запрещает склейку, какой бы похожей ни была внешность. Поэтому вокруг точных проходов стоят две поправки. До них по парам с почти одинаковой внешностью считается систематический сдвиг камер, если он больше 0.4 м. После них проход спасения соединяет оставшиеся разорванные куски разных камер: сходство внешности от 0.90, ровное смещение на плане, и ни одна камера не видела оба куска одновременно. Проверка на EPFL с намеренно сдвинутыми камерами: `scripts/eval_calib_noise.py`.

### 3. Сквозной трек: начало и конец (своя разработка, модуль `mtmc/tracks.py`)

Склейка даёт «вероятно одного человека». Трек — это **непрерывное наблюдение** этого человека, поэтому склейка нарезается на треки так:

- **Конец трека — выход из всех камер.** Если человека не видит ни одна камера дольше `tracks.end_gap_s` (2 с), и это не пропуск детекции (следующий пункт), трек завершён. Когда человек появится снова, это будет новый трек, даже если внешность совпадает. Связь с прежним треком остаётся только подсказкой: «тот же человек P5».
- **Пропуск детекции ≠ конец трека.** ТЗ: «краткий пропуск отдельного обнаружения не обязательно означает конец трека». Человек пропал дольше 2 с, но ID сохраняется, если выполнены все условия:
  - он исчез и появился **внутри зоны обзора камеры**, не ближе 0.5 м к её краю — то есть не у края кадра, откуда уходят;
  - он не в **зоне выхода** паспорта (`zones.<имя>.leads_to`, например дверь);
  - пропуск длился ≤ 8 с;
  - человек появился рядом: не дальше 1 м + 1.5 м/с × длительность пропуска.

  Пример: человека заслонили посреди комнаты, детектор его потерял, а через 6 с снова нашёл на том же месте.
- **Короткие пропуски** меньше 2 с трек не рвут: это потеря детекции или переход между камерами.
- **Переход между камерами.** Если вторая камера видит человека в той же точке плана, пока первая его ещё видит или потеряла меньше 2 с назад, ID трека сохраняется.
- **Дубль.** Трек, который идёт одновременно с другим, поглощается им в двух случаях:
  - ≥ 80% времени он ближе 0.8 м к другому треку;
  - он целиком внутри другого по времени, ближе 2 м и выглядит так же (сходство внешности ≥ 0.93). Это случай расхождения калибровок на краю кадра: один человек на двух камерах попадает в места плана в 1.5 м друг от друга.
- **Фантом.** Трек видела только одна камера, хотя место попадало в зону обзора ещё двух (зона — рамка кадра на плане). Это ложная детекция: отражение, плакат, стул.
- **Призрак.** Короткий трек (до 15 с), у которого сразу и плохое качество, и большое перекрытие другим человеком, и низкая уверенность детектора. Это ложная детекция рядом с людьми. Каждый признак по отдельности бывает и у настоящего человека, поэтому нужны все три. Значения подобраны на EPFL: у людей качество ≥ 0.23 и перекрытие ≤ 0.19, у ложного трека 0.07 и 0.45.
- **Шум.** Треки короче 2 с или с меньше чем 10 наблюдениями в счёт не идут.

**Порядок шагов:**

1. нарезка по паузам;
2. дубли и фантомы;
3. сшивка пропусков детекции;
4. ещё раз дубли, с ослабленным правилом: трек внутри другого с допуском 2 с, а на расстоянии до 1 м хватает сходства 0.90. Раньше сшивки это правило применять нельзя: оно забрало бы обрывок человека к его параллельной копии, и обрывки уже не сшились бы;
5. отбор: короткие, призраки.

Всё отброшенное попадает в `rejected_tracks.csv` с причиной и номерами треклетов. Посмотреть любой случай на видео: `python -m mtmc render --tid <номер> --clip`. Это и есть сбор сложных примеров: ложные срабатывания не исчезают молча, их можно разобрать и настроить правила.

**Зона обзора камеры** — рамка кадра, спроецированная на план по гомографии. Верх кадра за горизонтом отрезается. Без гомографии зона обзора — оболочка точек, где камера видела людей. **Положение камеры** на плане берётся из `site.json`, а если его нет — вычисляется из её гомографии.

**Повторяемость.** Перед обработкой фиксируются генераторы случайных чисел и включаются детерминированные свёртки cuDNN. Склейка и треки детерминированы: жадные шаги с однозначным порядком. Проверка: `python scripts/check_repro.py` дважды прогоняет всё с нуля и сравнивает `tracks.csv`, `persons.csv` и ID наблюдений.

### 4. Люди: все треки одного человека

Если человек ушёл из всех камер и вернулся, это **новый трек**, как требует ТЗ. Но программа старается понять, что это тот же человек (`P1`, `P2`, …), и собирает все его треки. Так получается список моментов, когда его видела хотя бы одна камера.

**Как треки собираются в человека:**

1. Треки одного человека из склейки, разорванные паузой во всех камерах, сразу считаются одним человеком.
2. Остальные пары треков объединяются по внешности, от самых похожих к менее похожим. Условия:
   - сходство прототипов OSNet ≥ 0.88, и ни одна пара треков в получившейся группе не ниже 0.80;
   - треки одного человека **не идут одновременно** (допуск 0.5 с).

Пороги выбраны по EPFL: куски одного человека совпадают на 0.95–0.997, разные люди — не выше 0.80.

**Проверка.** В записях EPFL никто не уходит из всех камер, поэтому выход и возвращение имитировались: каждый основной трек разрезан на начало и конец, а середина выброшена. Результат:

- 4p: 8 кусков собраны в 4 человека без ошибок;
- 6p: 12 кусков — в 6 человек без ошибок.

**Где смотреть:**

- `<data>/persons.csv` — по человеку: его треки, интервалы «в обзоре», промежутки «не виден ни одной камерой», камеры и по какому признаку узнан;
- в интерфейсе вкладка «Люди»: щелчок подсвечивает все треки человека на видео, на шкале времени и на плане.

Ошибка такой склейки — два похоже одетых человека, которые никогда не были в кадре одновременно. Это ограничение любой Re-ID только по внешности.

**Число уникальных сквозных треков** = число треков после этих правил. Трек, прошедший через несколько камер, считается один раз.

### Что сделано готовыми компонентами, а что своё

| Готовое | Своё |
| --- | --- |
| YOLO11m-pose: детекция и поза | Точка ног, проекция на план, качество наблюдения |
| YOLO11m-seg: маски людей | Сопоставление маски с найденным человеком, контур силуэта |
| BoT-SORT: трекинг в одной камере | Нарезка на треклеты: пауза, скачок, перекрытие, внешность |
| OSNet: вектор внешности | Склейка между камерами: признаки, запреты, объединение |
| OpenCV, ffmpeg, SQLite, parquet | Сквозные треки: конец трека, дубли, фантомы, шум |
| — | Интерфейс, калибровка по плану, хранение |

Готовые модели межкамерного трекинга не используются.

## Результат на EPFL Laboratory (4 камеры, 25 кадров/с)

| Запись | Длительность | Людей | Сквозных треков | Проверка |
| --- | --- | --- | --- | --- |
| 4p | 2:36 | 4 | **4** | Разметки нет. Каждый трек — один человек на всей записи (проверено по кадрам). |
| 6p | 1:58 | 6, никто не выходит | **6** | По разметке: все 6 человек — каждый одним непрерывным треком. Было 9 треков; правила «пропуск детекции» и «дубль по внешности» убрали разрыв и дубль шестого человека, «призрак» — ложную детекцию на 4 с. |

На 6p склейка по разметке даёт полноту 91.8% и чистоту 98.5%.

### Проверка

Метрики выше получены на EPFL Lab: одна комната, 4 перекрывающиеся камеры, 360×288, люди 80–150 px в кадре, никто не выходит. На них же подобраны пороги, поэтому это защита от ухудшения, а не независимая оценка. Для офиса первым делом смотрите раздел «Условия съёмки» в `report.md`.

`python scripts/control.py` — одна и та же проверка для каждой версии, минута без нейросетей. Она проверяет:

- число треков равно числу людей (4p и 6p);
- чистоту и полноту на 6p по разметке;
- завершение трека. В записях никто не выходит, поэтому уход имитируется: у каждого основного трека вырезаются все наблюдения на время окна. Пропуск 1 с трек не рвёт, уход на 12 с завершает его и начинает новый.

Итоги дописываются в `control_history.csv`, так что версии можно сравнивать на одном наборе.

### Цена ошибок

| Ошибка | Что видит проверяющий | Как настроено |
| --- | --- | --- |
| Разные люди склеены | Один ID ходит на двух людях; счёт занижен | Самая дорогая: склейка требует совпадения на плане, разные люди далеко друг от друга запрещены |
| Один человек разбит | Смена ID при переходе; счёт завышен | Дешевле, но заметна: её снижают дубли и сшивка пропусков |
| Трек продолжен через настоящий уход | Нарушение прямого требования ТЗ | Сшивка только внутри зоны обзора, рядом с местом исчезновения, до 8 с |
| Ложный трек в счёте | Счёт завышен | Фантомы и призраки; настоящего человека они тоже могут отбросить, поэтому всё отброшенное видно в `rejected_tracks.csv` |

Порог сшивки — главный компромисс: длиннее `detect_gap_max_s` — меньше разрывов при перекрытиях, но больше риск продолжить трек через настоящий уход. Если организаторы размечают выходы, этот риск снижают зоны `leads_to`.

## Автопривязка камер к плану (`mtmc/autocalib.py`)

Порядок: `process` без H → `autocalib` → `link` → `tracks` → `ui`. Или одной командой: `run --autocalib --manual --site site.json`.

```bash
python -m mtmc autocalib --data results_office --site configs/office/site.json --passports "configs/office/cam*.json" --manual
```

**Что нужно в `site.json`:**

- картинка плана со стенами тёмными линиями и масштаб `px_per_m`;
- для каждой камеры `pos` — точка на полу под камерой.

Необязательно, но сильно помогает:

- `look_at` — любая точка, куда смотрит камера;
- `height_m` — высота подвеса.

**Как работает:**

1. **Камера по людям.** Человек стоит вертикально и в среднем ростом 1.70 м. По сотням людей на разной глубине подбираются наклон, крен и высота камеры, а из них — гомография «пиксель → пол в метрах».

   Фокус по людям определяется плохо: на EPFL оценка завышалась в 2.3 раза. Поэтому перебираются типичные углы обзора 45–105°. Выбирается тот, при котором камера лучше совпадает с соседними. Если общих зон с соседями нет — берётся 65°.
2. **Поворот на плане.** Камера видит пол, значит отрезок «камера → человек» на плане не пересекает стен. Перебираются все повороты; если задан `look_at` — только около него.
3. **Совместное уточнение всех камер.** Люди, которых одновременно видят две камеры, должны попасть в одно место плана. Уточняются поворот, сдвиг (до 0.5 м от `pos`) и масштаб (±15%).
4. **Статус каждой камеры.**
   - **ok** — привязка записана в паспорт.
   - **check** — записана, но посмотрите картинку `calib_check/camN.png`: жёлтая сетка 1 м должна лечь на пол.
   - **fail** — с ключом `--manual` откроется окно ручной привязки. Без него программа напечатает команду `calibrate`.

   Причина статуса пишется словами: «много точек за стенами», «поворот неоднозначен», «расходится с соседями на 0.9 м» и т.п. Старый паспорт сохраняется в `*.before_autocalib.json`.

**Проверка на EPFL** (`scripts/eval_autocalib.py`).

Условия:

- использована настоящая калибровка EPFL;
- план — условная прямоугольная комната;
- положения камер отмечены с ошибкой 0.3 м.

Ошибка положения людей на плане (медиана по камерам):

| Запись | Только план | План + направление камеры |
| --- | --- | --- |
| 6p | 0.12–0.29 м, все 4 камеры «ok» | 0.11–0.33 м |
| 4p | 0.13–0.32 м | 0.29–0.39 м |

Если положение камер отмечено с ошибкой 1.5 м, ни одна камера не получает «ok»: две — «check», две — «fail».

**Сквозная проверка** (`scripts/eval_autocalib_e2e.py`): ручная привязка удалена, вместо неё автопривязка, затем `link` и `tracks`. Работает на копии данных.

- **4p:** все камеры привязались автоматически. Получилось 4 трека и 4 человека — то же, что с настоящей калибровкой.
- **6p:** 8 треков, с настоящей калибровкой — 7.
  - Все шестеро прослежены каждый одним треком.
  - Лишние два — короткие ложные детекции: на 9 с у одной камеры и на 4.6 с в конце записи.

Попутно выяснилось, что масштаб EPFL (0.025 м на единицу) завышен примерно на 30%. По росту людей правильнее около 0.019.

**Где автопривязка не справится:**

- сильная дисторсия (fisheye);
- в кадре почти нет стоящих людей в полный рост: нужно ≥ 150 наблюдений;
- все люди на одной глубине;
- план без стен и без `look_at`, а с соседними камерами нет общих зон;
- стеклянные перегородки: на плане это стена, а камера через них видит.
- положение камеры отмечено грубо, с ошибкой больше 0.5–1 м.

Во всех этих случаях статус будет «check» или «fail», и камеру нужно привязать вручную.

## Где алгоритм ошибается (пример с 6p)

**Ложный трек (1:25–1:29, 4 с, камеры 2 и 3).** Короткая ложная детекция рядом с двумя людьми, в 1–1.5 м от них. Внешне она на них не похожа (сходство 0.37–0.42), поэтому за дубль не принята. Её видели две камеры, поэтому и «фантомом» она не считается. Раньше из-за неё получалось 7 треков при 6 людях; теперь её отсекает правило «призрак» по качеству наблюдений. Такой же ложный трек с хорошей оценкой качества прошёл бы в счёт.

**Как было до доработки и что исправлено.** Шестой человек ходил у края комнаты, где гомографии камер расходятся на 1.4–1.9 м. Склейка разнесла его наблюдения в две группы, а 6-секундный пропуск детекции разрезал одну из них — получалось три ID. Теперь исправлено:

- пропуск внутри зоны обзора сшивается;
- параллельная копия с той же внешностью поглощается как дубль.

**Где правила могут ошибиться:**

- Человек сел за стол посреди комнаты и через 5 с ушёл через проход, не размеченный как зона выхода. Трек ошибочно продолжится — это не «пропуск детекции». Нужны зоны `leads_to` у всех выходов.
- Два одинаково одетых человека (форма) у края кадра. Один может быть принят за дубль другого.

**Типовые причины ошибок:**

- неточная калибровка на краях кадра;
- долгое полное перекрытие толпой — выглядит как выход из всех камер;
- два похоже одетых человека, идущие вплотную: их можно принять за дубль и склеить;
- человек, которого видит одна камера в зоне, «покрытой» другими (например, он сидит за столом): его можно принять за фантом.

## Ограничения и что улучшить

**Ограничения:**

- Пороги подобраны на EPFL. Для офиса стоит проверить:
  - `tracks.end_gap_s` — сколько длится проход между камерами;
  - `link.d_same_m` — точность калибровки.
- Выходы (двери, лестницы) нужно разметить в паспорте как зоны с `leads_to`. Иначе выходом считается только край зоны обзора камеры.

**Что улучшить:**

- Предсказание движения (фильтр Калмана) в слепых зонах между камерами.
- Склейка камер без привязки к плану. Сейчас такая камера остаётся отдельной: `mtmc/link.py` не проверяет передачу без плана.
- Дообучение Re-ID на офисных кропах.
