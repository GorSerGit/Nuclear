# Архитектура решения

## Контекст

Кейс NtechLab: пять синхронных камер офиса сложной планировки (широкоугольные объективы 108–119°, 2592×1944).
Нужно связать наблюдения одного человека на кадрах и камерах в сквозной трек с неизменным ID, завершать трек только
при выходе из обзора всех камер дольше порога (2 с), посчитать уникальные треки и показать их в интерфейсе.
Готовые модели межкамерного трекинга не используются.

Главный признак склейки — **положение на плане этажа в метрах**, внешность (Re-ID) — вторичная проверка и вето.

## Компоненты

```
видео камер ──► 1. одна камера ──► 2. треклеты ──► 3. склейка между камерами ──► 4. сквозные треки ──► 5. интерфейс
               YOLO11-pose        нарезка по       положение на плане,            конец трека = выход    синхронное видео,
               BoT-SORT           паузе, скачку,   время, скорость,               из всех камер > 2 с;   силуэты, план,
               YOLO11-seg         внешности        внешность (PersonViT)          дубли, фантомы, шум    аналитика
```

| Этап | Модуль | Что делает |
| --- | --- | --- |
| Одна камера | `mtmc/detect_track.py`, `mtmc/observation.py` | YOLO11m-pose: рамка и 17 точек позы; BoT-SORT: трек внутри камеры; точка опоры по щиколоткам или пропорциям тела; отбрасывание детекций в `ignore_zones` (экраны, зеркала, плакат) |
| Геометрия | `mtmc/lens.py`, `mtmc/geometry.py`, `mtmc/calibrate.py`, `mtmc/autocalib.py` | выпрямление «рыбьего глаза» (равноудалённая модель r = f·θ, f ≈ 1244–1374 px), гомография пол → план в метрах по 6–10 парам точек, уточнение по людям, видимым двумя камерами |
| Силуэты | `mtmc/silhouette.py` | YOLO11m-seg; маска сопоставляется с человеком по рамке (IoU ≥ 0.5), контур до 48 вершин |
| Треклеты | `mtmc/tracklets.py` | разрез трека трекера: пауза > 1.5 с, скачок на плане > 3 м/с, резкая смена внешности |
| Внешность | `mtmc/reid.py` | PersonViT (MSMT17), из вектора вычитается средний вектор камеры (свет и неон); пороги 0.40–0.45 |
| Склейка | `mtmc/link.py` | одновременные треклеты разных камер ближе 0.6 м + погрешность; последовательные — пауза до 8 с, скорость до 2 м/с, запас 1.5 м на передаче между камерами; запреты: два треклета одной камеры одновременно, расхождение на плане > 1.5 м |
| Сквозные треки | `mtmc/tracks.py` | конец трека, когда никто не видит человека > 2 с; сшивка пропуска детекции внутри зоны обзора (до 8 с, рядом с местом исчезновения); дубли, фантомы, призраки, шум короче 2 с |
| Люди | `mtmc/tracks.py`, `persons.csv` | треки одного человека, ушедшего и вернувшегося, собираются в P-номер по внешности; это подсказка, счёт треков не меняет |
| Интерфейс | `mtmc/ui.py`, `mtmc/ui_static/`, `scripts/office_web.py` | веб-приложение: загрузка видео, разметка камер и плана, запуск обработки, просмотр результатов |

## Основные технические решения

- **Геометрия вместо чистого Re-ID.** Двух людей в разных местах плана нельзя склеить, как бы похоже они ни были одеты;
  внешность только подтверждает продолжение и запрещает явно разных.
- **Нарезка на надёжные треклеты.** Трекер внутри камеры путает людей при перекрытиях, поэтому трек режется на куски,
  где человек точно один, и склеивается уже глобально.
- **Конец трека по ТЗ.** Новый трек начинается, только если человека никто не видит дольше 2 с и это не пропуск детекции
  внутри зоны обзора. Связь «тот же человек» после ухода хранится отдельно (P-номер).
- **Ничего не теряется молча.** Всё отброшенное (дубли, фантомы, шум) попадает в `rejected_tracks.csv` с причиной.
- **Детерминированность.** Фиксированные генераторы, детерминированные свёртки, жадные шаги склейки с однозначным порядком.
- **Аналитика в интерфейсе.** Вкладка «Аналитика»: 3D-вид сверху, поиск по цвету одежды, времени и камере,
  видеоотчёт по человеку (webm), подсчёт проходов через линию, время в зонах и пик одновременного присутствия.

### Готовые компоненты и своя разработка

| Готовое | Своё |
| --- | --- |
| YOLO11m-pose (ultralytics) — детекция и поза | точка опоры, проекция на план, качество наблюдения |
| YOLO11m-seg — маски людей | сопоставление маски с человеком, контур силуэта |
| BoT-SORT — трекинг в одной камере | нарезка на треклеты |
| PersonViT, OSNet — векторы внешности | склейка между камерами: признаки, запреты, объединение |
| OpenCV, ffmpeg, SQLite, parquet | сквозные треки, выпрямление объектива, калибровка, интерфейс и аналитика |

## Зависимости

См. [`requirements.txt`](../requirements.txt) и раздел «Зависимости» в [README](../README.md).
Python 3.13, PyTorch 2.7, ultralytics 8.4, torchreid, timm, OpenCV, pandas, pyarrow. Интерфейс — HTML5 и JavaScript без внешних библиотек.

## Безопасность и приватность

- Обработка полностью локальная: видео и результаты не отправляются в сеть, интерфейс работает без интернета.
- Хранятся кропы людей и векторы внешности — это персональные данные, папки результатов не стоит публиковать без согласия.
- Распознавания лиц и идентификации личности нет: ID трека и P-номер — условные номера внутри одной записи.
